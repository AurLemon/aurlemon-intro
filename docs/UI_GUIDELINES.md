# UI 规范

适用于页面、组件、样式和交互改动。

## 视觉迭代

- 不要在未明确要求时额外添加 hover 浮动、缩放、过强动效或重排版交互。
- 对现有样式做修改时，优先基于用户已改过的版本继续迭代，不要擅自回退视觉方向。

## 首页卡片动态背景

六张首页卡片统一使用重复素材背景，旧的整张背景图已经删除。`InfoCard` 只负责前景布局、边框、背景插槽与内容切换，不再提供 `backgroundSrc`、`backgroundBlur` 或 `darkInvert`。

### 移动端与桌面模式

- `useDisplayMode` 是布局与动效模式的统一入口：`isCompact` 使用 `< 64rem`（与 Tailwind lg 一致）决定布局；`isMobileMotion` 在窄屏或缺少 hover + fine pointer 时使用轻量动效。`plugins/display-mode.client.ts` 只在 hydration 完成后同步共享状态，并监听媒体条件变化；SSR 与首次 hydration 保持一致，必要的窄屏静态 CSS 在同步前已经生效。不在业务组件内重复维护不同的“手机”断点。
- 桌面保持双层背景、完整平铺周期与原有交叉淡化；轻量模式只渲染普通状态一层，平面只保留旋转与滤镜余量，取消漂移和常驻 will-change。布局与平铺尺寸计算位于 `useCardPatternLayout`，素材、透明度与档位仍沿用 `cardPattern.ts`。
- 触摸不触发卡片 hover，指针焦点不展开上方导航提示；键盘通过 focus-visible 保留可达性。窄屏不在卡片内挂载导航提示，改由 `MobileCardNavigationStack` 投放到 Header 下方；`useMobileCardNavigationStack` 用 IntersectionObserver 维护上半屏内的卡片，卡片进入立即显示、离开通过轻微 translateY 与 opacity 动画退场，不压扁缩放，不等待停滚；静止展示 4 秒后移除，滚动期间暂停该倒计时，停滚 180ms 后重新计时。最多堆叠三条，统一 18rem 宽度（不超过可用宽度）；参考 Nuxt UI Toaster 的错位与每层 5% 缩放，用实色表面、边框和小阴影表现堆叠，不降低后层透明度。只动画 transform / opacity，后层透明度保持不变，上下 padding 为 0.25rem；被动 scroll 监听仅负责静止计时，不逐帧测量、不使用 UNotifications；离开页面、模式切换及页面隐藏时清理观察器和定时器。宽屏轻量模式的导航提示不播放尺寸、裁切和模糊动画。Header blur 与底部浮动菜单保留用户确认的原有视觉效果；先通过背景、布局和触摸触发范围降低开销，不默认删除这两处效果。
- ACG 与音乐离开视口时暂停轮换和作品名滚动，返回后继续剩余阅读时间，弹窗与页面隐藏暂停叠加处理。真实下一张封面通过 `prepareCardCover` 提前下载与解码，切换仍等待准备完成，失败不消耗队列。轻量模式作品名按实际内容与宽度上限计算，短内容收缩、长内容滚动；只在内容/布局变化时更新宽度，不播放 width 过渡，桌面保留既有宽度过渡。
- 窄屏学历卡片校徽靠左、文字列占满剩余宽度，始终使用全称并在溢出时滚动，不播放校徽与简称组合收拢；桌面保持原行为。学校文字的动画关键帧独立放在 `educationSchoolMotion.ts`。
- 首页少量前景图片使用 eager；`SkeletonImage` 的 `revealCachedImmediately` 仅由首页调用方启用，已缓存且完成解码的图片直接展示，其他调用方仍保留默认 lazy 和渐显。不把全站图片改为 eager。
- 性能验收必须额外覆盖首次进入后立刻从顶部滑到末尾、连续上下滑动、卡片首次露出、菜单显隐与偏好轮换；生产 trace 用于性能判断，Dev 只用于快速检查。短距离热页面对照与 Build 都不能证明完整移动体验通过。

### 共用层与默认值

- `CardPatternBackground` 统一接管固定排列、密度、列错位、倾斜、遮罩、明暗配色、透明度、模糊过渡、阴影、滚动、视口/页面隐藏暂停与减少动态效果。素材组件只负责校徽、图片裁切或 SVG 镂空，不自行复制动效和视觉参数。
- `components/cards/cardPattern.ts` 是参数唯一入口。`visibility` 表示与主题底色的目标 RMS 色差，不是 CSS opacity；默认浅色 0.036、深色 0.057，hover/内部聚焦分别为 0.075、0.0762。教育背景不随学历选择高亮或压暗，切换只更新前景校徽与文字。已删除无调用方的 selectedMotif、背景分层选中高亮及独立选中透明度配置。六张卡片使用相同基础目标，素材差异通过公共档位处理，不在卡片内散落独立数值。浅色视觉强度略弱于深色；具体 CSS opacity 可能反而更高，因为浅色底与灰色素材的对比更低。
- 每个素材独立计算 `opacity = min(0.6, visibility / contrast)`，纯透明或与底色完全同色的素材保持不可见，不无限放大。使用亮度权重的 sRGB 色差 RMS 作为项目内的近似视觉指标，包含透明覆盖面积、色彩和饱和度调整效果；它不保证不同图案的主观观感完全相等，也不是正文 WCAG 对比度。静态径向遮罩与阴影仍统一施加，不把前景附近的刻意渐隐补偿回来。
- `build/card-appearance/nuxt.ts` 在 Dev/Build 中按 48px 单元格、42px 素材测量各主题；色票读取当前 `assets/styles/base/tailwind.css` 的 surface-0、neutral-500/400。素材先按实际 contain/cover 裁切、保留 alpha、按共用 `saturate(1.15)` 增强饱和度，再模拟 Gaussian blur，输出色差和梯度 RMS 的保留率。测量只在构建侧发生，不由客户端逐张下载原图或用 Canvas 分析。
- 模糊统一以 64px 单元格为配置基准：普通状态 3px，hover/内部聚焦 1.5px，实际值按 `clamp(36px, 14cqw, 64px) / 64` 同比计算。采样表按 48px 单元格换算并线性插值色差，再反算透明度；不会继续用边缘保留阈值把用户设定的模糊压到过小，也不会让静态与 hover 算成相同值。构建输出的边缘保留率作为测量元数据保留。SVG 文本采样使用构建主机 serif 字体，浏览器继续用项目 serif 字体，字形差异会带来小幅测量误差。
- 公共档位位于 `cardPattern.ts`：`blurLevel` 的 `clear / standard / soft` 分别乘 0.65 / 1 / 1.15；`strengthLevel` 的 `quiet / subtle / standard / distinct` 分别乘 0.5 / 0.8 / 1 / 1.2。先继承公共默认值和部分字段覆盖，再应用档位。技术、夜间与语言当前使用 `density: 1` 和默认 standard 档位，语言文字字号为 18；ACG 与音乐都使用 clear + distinct，保持相同目标可见度；教育使用 standard + subtle 和 `density: 0.95`，较默认 0.8 略密，在常见桌面卡片宽度下约多一列，保持更柔和的校徽背景。
- `options.density` 按比例缩小单元格；布局测量、模糊与移动距离同步使用该单元格尺寸。`columnStep` / `rowStep` 分别独立控制横向列距和纵向行距，默认均为 1 个单元格，不改变素材大小；图片背景默认按素材显示宽度加 0.12 格留白计算，竖版封面为 0.62 + 0.12 = 0.74，未指定尺寸的方形图片仍为 1，可通过 options 覆盖列距。音乐通过 `imageWidth: 0.62` 与 ACG 使用相同显示宽度、density 0.7 和 0.12 格间隙，正方形素材行距为 0.74，不沿用竖图的 1 格行距。音乐使用 catalog 排列，四列、八行覆盖全部 29 张，补齐空位的少量图片重复；悬停以原速度持续向下滚动完整八行周期（40 秒），循环接缝与起点图案重合。其他背景同样移动各自完整的平铺周期，保持既有排列。`options` 按需提供 `light`、`dark` 的目标可见度与参考尺寸 blur、`shadow` 部分字段，以及 `transitionMs`、`driftSecondsPerRow`。未提供字段继承公共默认值。常规卡片只传素材和构建输出的 `profiles`，不得再手填每个素材的透明度。色票、图片或 SVG 清单修改后重新生成测量结果。
- 普通与 hover 各渲染一份固定 blur、固定素材 opacity 的 SVG 图案，hover 用外层 HTML 的 500ms ease-out opacity 交叉淡化模拟清晰度与强度变化。禁止逐帧改变重复 SVG 素材的 opacity 或 blur/filter；这会让快速换卡片时的退场过渡一起重绘。两份图案共享素材 URL，不增加下载。主题数值在挂载后读取 `useColorMode`，SSR 与首次 hydration 使用相同默认值，避免深色主题样式不一致；素材内联取值，不依赖 SVG use 引用树的祖先主题/hover 选择器。教育菜单打开时通过 `focusActive` 关闭焦点播放，保持既有交互。
- 四类素材通过 `motifs` 和 `motif` 插槽接入：`EducationCardBackground` 只传校徽与测量值，`TechnologyCardBackground` 和 `PersonalCardBackground` 通过 `SvgCardBackground` 使用受信任的本地 `*.card-motifs.json?appearance` 清单，渲染和测量共用同一份 SVG，`ImageCardBackground` 从一个图集 URL 按区域裁切。六张卡片的每个静态状态均合并为一个 SVG pattern 层；教育阶段切换不改变背景图案或强度。图案层数不等于图片请求数。公共层统一交互和视觉参数，素材层保留不同的外轮廓，不要求每个主题都套相同的圆角底块。

### 排列、阴影与交互

- 固定排列避免 SSR 随机差异。倾斜 -12°，相邻列上下错半格；单元格 `clamp(36px, 14cqw, 64px)`，素材占 88%，补齐跨边界半格。绘制平面通过 ResizeObserver 按卡片逆旋转后的包围盒计算，横向加一格滤镜余量、纵向加两个完整平铺周期及一格滤镜余量，避免固定绘制 20 × 12 格。前景尺寸与文字布局不随背景调整。
- 静态径向透明遮罩使用 `ellipse at center`：20% 位置不透明度 25%、65% 为 60%、100% 为 100%。前景后方保持安静，不叠加固定颜色盖住文字。
- 所有六张背景素材的阴影统一在共用组件 SVG `g` 上复用 `feDropShadow`。默认以单元格为坐标：水平偏移 0、垂直偏移 0.025、标准差 0.022，浅色 `slate-700`、深色 `slate-950`、阴影不透明度 55%。阴影仍受整体透明度、模糊与遮罩约束；校徽按真实透明轮廓投影，镂空图案保留空洞边缘，不叠加第二套阴影。
- hover/内部聚焦时沿倾斜的列方向持续向下移动，默认每行 5 秒；移动距离自动取 SVG pattern 的完整纵向平铺周期（`tileRows × rowStep`），周期时长为 `tileRows × driftSecondsPerRow`，使用 linear infinite 单向动画，结束位置与起点图案完全重合，实现无感循环，仅持续动画 `transform`。移出保留当前位置；离开视口或页面隐藏暂停。两份静态图案同步移动，模糊和素材强度在每份图案内部保持固定，仅外层状态 opacity 与移动容器 transform 动画。只对这两个明确的动画容器使用 will-change，不向全部 SVG 节点添加；可见性观察稳定的卡片盒，不观察带遮罩的背景；离开视口、页面隐藏和减少动态效果时释放提示。
- 装饰背景不接收指针事件且隐藏于无障碍树。减少动态效果时禁用滚动和渐变过渡，保留静态背景。验证覆盖静态/hover、教育阶段切换、明暗主题与窄屏；Build 不代替浏览器验收。

### 图片清单与请求预算

- 首页素材统一放在 `assets/resources/homepage/` 的六个子目录：`education / technology / acg / music / night / language`。各卡片的图片清单和 SVG 清单与素材同目录，统一命名为 `background.card-atlas.json` 或 `background.card-motifs.json`，前景单图为 `cover.svg` / `cover.webp`；教育目录保存四个校徽。ACG 封面使用作品名与卷数命名，统一保存全尺寸 WebP，条目来源仍可通过清单 id 中的 Bangumi 编号追溯。

- ACG 和音乐分别使用 `assets/resources/homepage/acg/background.card-atlas.json`、`music/background.card-atlas.json` 保存实际素材清单：每项包含稳定 `id` 和相对清单的本地 `file`。ACG 使用用户选定的六张 Bangumi 竖版封面（本地 `acg/`），通过清单 `fit: "portrait"` 固定宽度并按原图宽高比自动计算高度，不裁切；音乐背景使用用户提供的二十九张网易云封面直链，清单 `source` 字段保留来源记录，构建与浏览器不会从这些直链实时抓取；前景通过 `MusicCardCover` 从同一清单的 `?covers` 导出中只显示一张 320px 缩略图，`cover.webp` 已删除。不自动抓取网络图片、不临时填充示例素材。
- 使用静态导入 `import atlas from '~/assets/resources/homepage/acg/background.card-atlas.json?atlas'`。`build/card-atlas/module.ts` 在 Dev/Build 中解析清单；单图复用已有 `?w=320&q=90&thumbnail` URL，单图模式前景和背景复用同一个资源；多图模式背景图集与按需前景缩略图各自独立。多图构建为一个 WebP 图集，每格 160 × 160，最多 32 张，单图集不超过 200 KiB，质量 85。图集只写入已忽略的构建目录 `card-atlases/`，原图保留，最终 URL 由 Vite 打包并缓存。清单可设置 `fit: "contain"` 在透明方格内完整容纳图片；ACG 使用 `fit: "portrait"`，图集区域宽度固定为 112px，高度按原图宽高比等比缩放，打包行高按最高素材自动扩展，不随机、不裁切、不拉伸。显示宽度统一为单元格的 62%，高度按区域比例变化，ACG 与音乐均使用 `density: 0.7`，较公共 0.8 在同宽卡片上约少一列，其他公共参数保持不变；默认 `cover` 保留既有方形裁切。
- 多图的 `CardImageAtlas` 只含一个 URL、尺寸和裁切区域；客户端不接收原图 URL 列表，不对每个格子发起独立请求。尺寸与裁切在构建时确定，浏览器仍实时做列排列、旋转与移动，不能把图集理解成旧式整张背景图。
- 图集按清单、原图内容、尺寸和 sharp 版本计算缓存指纹。清单或已引用素材变化时 Dev 刷新并重建；缺失、不支持、重复 id、超过数量或体积预算时明确报错。仅支持仓库 `assets/` 内静态 PNG/JPEG/WebP/AVIF，不在请求处理时现场拼接图片。
- 教育的四个校徽本来就供前景切换使用，前景、预加载和背景共享 320px/q90 缩略图 URL，重复图案不增加独立下载；保留用户已确认的预加载行为；`*.webp?appearance` 仅导出分析数值，不生成另一张图片。技术、夜间与语言背景使用内联 SVG/文字，不新增图片请求。后续下载用户选定链接后保存原图并修改清单即可；需要自动更新时另行设计定时获取、生成、原子发布与失败时保留上一版，不默认加入后端更新服务。

### 前景布局与颜色

- 六张卡片的前景图统一由 `InfoCard` 的 logo 插槽容器禁止选中与原生拖拽，覆盖图片、SVG、Emoji、学历切换及偏好轮播的进出场图层；保留其他文字与链接的交互。`select-none` 只限制选中，不能单独阻止图片拖拽；容器同时阻止 `dragstart`，图片补充 `-webkit-user-drag: none`。

- 六张卡片继承 `InfoCard` 的同一套外边框和文字颜色：外层 `h-40 rounded-xl border-6 border-slate-200 dark:border-slate-800`；标题 `text-slate-800 dark:text-slate-300`，副标题 `text-slate-700 dark:text-slate-400`。技术卡不再单独覆盖为更浅颜色。背景滚动、图片分类和副标题切换不得改变主标题。
- ACG 与音乐前景使用完整的 80 × 80 容器，外层 `rounded-lg overflow-hidden`，使用 `bg-slate-200/60 dark:bg-slate-800/60` 作为图片加载、失败与切换时的颜色兜底；常驻边框覆盖层使用 `border-slate-300/60 dark:border-slate-800/60`，与夜间、语言前景保持相同主题配色；图片贴满边缘，不加 margin、padding 或会挤占图片的布局边框。ACG 内层封面只使用 `rounded-sm`，层间有阴影，阴影不能漏出容器。教育背景也按内圆角裁切；教育菜单仍可溢出前景，不能直接裁掉整个 InfoCard。
- ACG 与音乐的 InfoCard 和前景行 DOM 常驻，只切换内部封面、副标题和作品名，不通过 contentKey 重建整行。启用 smoothWidth：分别测量固定标题与副标题的自然宽度，以可用空间为上限，用 500ms width 过渡推动文字列与封面；自然测量不能受到 line-clamp 或省略号影响。教育继续沿用其独立的校名过渡。
- 音乐主标题固定使用原来的 J-POP / Voca 文案；ACG 固定 GIRL LOVE。英文、日文副标题保持短句，并遵守文字列最大宽度，不能挤出卡片。底部作品名是加粗的非交互文本，不创建链接。

## 首页卡片导航提示

- 仅教育、技术、ACG、音乐四张卡片提供上方导航胶囊，分别链接本地化的 `/profile`、`/project`、`/preference`、`/preference`；后两张不提供。文案同步维护三种语言的 `main.index.card.navigation`，ACG 与音乐使用独立提示；通过 i18n-t 的 page 插槽将页面名显示为 font-bold 并加 px-0.5，浅色使用 slate-800、深色使用 slate-100；其余提示文字使用普通字重与 slate-500 / slate-400，hover 不将整句染成主色。指针移入小条或键盘聚焦时，外壳背景浅色从 surface-0 切到 surface-1、深色从 surface-1 切到 surface-2，以 180ms 颜色过渡提示可点击；不因指针仍在大卡片内而提前触发小条背景变化。

## 浮动菜单与首次交互性能

- Header 的主题、语言按钮及弹出菜单图标局部使用 `UIcon mode="svg"`，保留现有 clientBundle 图标清单。CSS 模式首次挂载图标会插入运行时样式表；本机 Chromium 采样中这会触发已有字体重新加载，让首页 Emoji 短暂回退并改变宽度。不要通过给 Emoji 固定宽度或增加全页合成提示掩盖这条触发路径，也不将局部修复扩展成全站图标模式切换。
- 选中高亮和指针预览使用常驻的普通 DOM，位置、按压缩放与淡化交给原生 CSS 过渡；不要每次进入菜单重新挂载 Motion/AnimatePresence。宽度仅保留菜单项尺寸变化所需的 220ms 过渡，位移 380ms、透明度 180ms；减少动态效果时关闭过渡。合成提示仅用于这两个小型高亮，不扩散到所有导航节点。
- 菜单项局部位置和尺寸在 `syncPills`（初始测量、菜单布局、语言、路由变化）时缓存；pointermove 只保留最新坐标，每帧最多读取一次视口和 inner 的变换后边界，不重复遍历读取每个链接的 getBoundingClientRect。离开菜单或卸载时取消待处理帧；保留触摸横向拖动、拖动后禁止误导航及键盘聚焦行为。
- 首次导航的卡顿需分别测量路由确认、内容挂载和菜单动效，不能把页面组件的主线程长任务全部归因于导航。Dev 首次模块编译、首次 hydration 与后续热导航不等价；帧采样/Long Task 只能辅助定位，不冒充完整 DevTools trace。
- 项目页贡献日历的真实色块保留普通 span，通过容器委托事件、日期索引与一个 UTooltip reference 显示日期和次数；不为一年约 365 个色块各初始化一套 Tooltip。指针提示保留 50ms 延迟，支持键盘聚焦；退出色块、滚动、重新加载和卸载时关闭并清理定时器。日期格式器按 locale 复用，数据获取与日历横向滚动不变。

- 教育阶段下拉框的中文补充小字：专科为“3+2 高职阶段”，高中为“3+2 中职阶段”。日语专科沿用标签右侧的小字位置，显示“短大相当”，简短说明教育层次；日语其他阶段和英语的 `hint` 保持空字符串，避免回退到中文。英文专科副标题仅展示年份，不附加 `DIPLOMA`。

## 品牌签名动画

- About 页的签名首次进入视口时播放一次：去掉整字描边提示，高亮与手写同时开始，高亮铺开 360ms，手写持续 2600ms，完成后保留静态标记，不循环擦除。
- `SiteMark` 通过 `duration` 和 `highlightDuration` 配置当前使用位置的节奏；动画默认时长为手写 4000ms、高亮 900ms，footer 使用静态标记，不播放动画。动画保留转弯减速，减弱连笔提速并平滑相邻速度采样，缩短抬笔停顿；减少动态效果偏好下静态展示。

## 样式实现

- 全局换行按内容语言决定，与设备无关：中文、日文使用 `word-break: break-all`，英文使用 `word-break: normal`；通过 `:lang()` 支持局部语言标注。介绍行和正文段落不再用 break-normal 覆盖中文、日文策略；nowrap、代码、URL 等有明确用途的局部规则仍可覆盖。

- HTML 结构中，非必要不要直接写 `style` 内联样式，优先使用 Tailwind CSS 与 Nuxt UI 提供的能力完成样式表达。
- `<style scoped>` 不是禁用，但应只用于 Tailwind CSS / Nuxt UI 难以表达的复杂状态、动画、第三方组件覆盖或结构性样式；普通布局与视觉优先留在模板 class。
- `:style` / 内联 `style` 只用于运行时计算值、第三方库注入 HTML、canvas / map 等 Tailwind CSS 无法静态表达的场景；静态样式不要回退成 inline style。

## 主题与 Design Token

- 优先复用 `app.config.ts` 中的 Nuxt UI 主题配置，以及 `assets/styles/base/tailwind.css` 中的 design token，不要在页面里重新发明一套颜色、表面层级、尺寸语义。
- 颜色、语义色、表面层级、字号与字体倾向，优先通过 token 与 class 表达，不要在局部组件里散落硬编码色值。
- 对 Nuxt UI 组件的定制，优先走 theme / config / class 扩展，不要为了一个局部视觉点把整个组件手写替换掉。
